## Правила работы
- **Дневные листы (фото).** Порядок фото обычно: 1 — Премиум, 2 — Яшнабад (если не сказано иначе).
  Сначала пересчитать каждую строку и итоги, сверить с листом, показать таблицей и
  расхождения списком вопросов. **Вносить только после команды «делай»** (или «добавляй»).
  Вопросы задавать одним сообщением, все сразу, не растягивать уточнения на несколько раундов.
  «Делаешь как всегда» = весь этот порядок.
- Если цена по частям больше записанной суммы — это скидка: скидку вычитаем из оправы
  (`price` = полная цена, `sum` = после скидки, `note` = «Чек X, оплачено Y — скидка Z»).
  «Общая скидка» — делить пропорционально по позициям чека.
- Названия расходов — как пишет владелец, не переименовывать; исправлять только цифры.
- Долги и задатки: записывать только оплаченную сумму (пропорционально по позициям),
  в `note` — «долг … не записан». Погашение долга — отдельная строка, cat «Погашения долгов»,
  product «Погашение долга … (продажа DD.MM)».
- Доллары — пересчитать в сумы по курсу с листа, курс указать в `note`.
- Подарок — `sum` 0 и пометка («оправа в подарок»).
- Словарь листов:
  - оплата: «пеймент»/«payme» = `QR/Payme`; «хумо»/«узкард» = `Терминал` + note «Оплата Humo/Uzcard»;
    Kaspi = `QR/Payme` + пометка; «пер» = `Перечисление`; «нал» = `Наличные`; несколько способов = `Смешанная` с `pays`;
  - товары: «з/л» = заказ линз («Линзы … (з/л)»); «стар» = Star; «сей» = Seiko; «блок» = Блок; «ЕТ» = ET;
    «4в1» = Линзы 4в1; «с/з» = солнцезащитные; «к/л» = контактные линзы; «дет. опр» = детская оправа;
    число вроде 5501 — код оправы («Оправа 5501»). Неясный тип линз — подобрать по цене или спросить.
- Сергели: продажи приходят из Billz сами, вручную не вносить. Расходы — из журнала Excel владельца
  (линзы, доставка, мастер, месячные доставка и бонус продавца): вписывать только то, чего нет, без дублей.
- Не просить заново файлы, которые уже присылались.
- Не удалять данные без явного согласия. Секретный ключ Billz никогда не показывать в чате
  (он хранится только как секрет Supabase `BILLZ_SECRET_TOKEN`).
- Репозиторий публичный: никаких реальных данных в `dev/` и в этом файле.

## Где что лежит (таблица `public.docs`: col, id, data jsonb)
- `sales` — продажи. id `sYYp01…` / `sYYy01…` (YY — число месяца, p — Премиум, y — Яшнабад).
  Поля: point, date (YYYY-MM-DD), check, cat, product, qty, price, sum, pay
  (`Наличные` | `Терминал` | `QR/Payme` | `Смешанная` с `pays`), note, createdAt.
  Uzcard/Humo → `Терминал` + note «Оплата Uzcard/Humo». Продажи Сергели приходят из Billz сами (id `bz_…`).
- `entries` — расходы: id `eDDN`, cat `op`, type `exp`, branch = точка, source `day`.
  Остаток наличных точки за день: id `bc10DDp` / `bc10DDy`, kind/source `bc`, type `inc`,
  amount = нал − расходы (или фактически на руках, с пометкой излишка/недостачи).
- `createdAt` — реальное время в мс, **не в будущем** (иначе ломается «наличка на руках»).
- `report` — выписка р/с Анор Банка по дням: id = дата, rsStart, rsEnd, bank [{a, n, c?}].
  Из выгрузки `payments_*.xlsx`: начало дня = остаток до первой операции дня,
  конец = после последней; дебетовые операции → `bank`. Воскресенья без операций не заводим.
  rsStart дня должен равняться rsEnd предыдущего.
  Если новая выписка расходится со старой — пересобрать дни по новой.
- Billz: `bz_check`, `bz_stock`, `bz_product`, `bz_transfer`; статусы выгрузок — `docs` col `sync`.
- `fiscal/<день>` — гросс фискальных модулей по точкам {pts:{точка:{c,n,k}}}; `settings/fiscal` — привязка
  модулей к точкам (номера модулей — только в базе, не в репозитории). Источник — Rahmat (hub.rhmt.uz):
  «Отчёт по чекам» выгружается в фоне, скачивается zip с Excel (безнал — колонка «Карта»).
  В кабинет Rahmat входит сам владелец, Claude только читает и ничего там не меняет, пароли не вводит.
  Раздел на сайте выключен, пока владелец не скажет включить.

## Карта кода (Graphify)
В `graphify-out/` лежит граф кода: функции, файлы и связи между ними (`graph.json`, обзор — `GRAPH_REPORT.md`,
картинка — `graph.html`). Graphify ставится сам при старте сессии (хук в `.claude/settings.json`);
если нет — `pip install graphifyy==0.9.97`.
- Прежде чем искать по коду (grep, чтение файлов), спросить граф: `graphify query "<вопрос>"`,
  связь двух вещей — `graphify path "<A>" "<B>"`, одна функция — `graphify explain "<имя>"`,
  что заденет правка — `graphify affected "<имя>"`. Потом читать только найденные строки.
- Код `dev/base.html` попадает в граф через зеркало `dev/graph-src/base.html.js`: **номера строк в нём
  совпадают с base.html**. Править всегда `base.html`, зеркало не трогать — оно пересоздаётся.
- `bash dev/build.sh` сам обновляет зеркало и граф (без LLM, бесплатно). Изменения в `graphify-out/`
  коммитить вместе с кодом; большой diff `graph.json` — это нормально.
